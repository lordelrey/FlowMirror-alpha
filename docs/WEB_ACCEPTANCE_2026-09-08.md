## 验收中发现并修掉的缺陷

按发现顺序，全部由 GLM 按卡修复、由本记录逐项复验。

1. **`/api/images/<sha>` 永远 404。** 展示包 `posts.json` 只带图片的 sha256（文件名不外泄），
   服务端却拿 sha 去查文件名表。结果：配了 `--images-root` 也永远看不到真图，而这是界面上
   唯一能看见真图的路径。改服务端按 sha 反查文件名，**每次请求仍重算 sha256 比对**。
2. **随仓库分发的样本打不开。** `loadRun` 只在 `runs/out/<tag>` 下找，样本在 `web/samples/`。
   在 Pages 上（没有 `runs/out/`）等于白分发。`data.js` 两条路径都失败后改为查一次
   `web/samples/index.json` 并按其 `path` 重试，命中时在 `warnings` 里注明"这是演示样本"。
3. **`modality.js` 被落盘工具写进了补丁标记**，整个模块语法错、该页打不开。见下节。

## 已知限制（不是缺陷，但读者应当知道）

- **静态模式下必有一条控制台 404**：`probeLocalApi()` 去问 `/api/runs` 在不在，静态服务当然
  没有。这是**探测本身**，不是错误；浏览器无法静默失败的 fetch。所以第 1 项的判据是
  「没有**意外的**控制台错误」，不是字面的零。
- **ES 模块受浏览器缓存影响**：`?cb=` 只作用于 `index.html`，`import './data.js'` 的 URL 不变，
  改动后首次打开可能仍跑旧模块。验收时靠换端口（换源）绕开。部署到 Pages 后，回访者也可能
  拿到旧模块——若在意，给模块 import 加版本查询串。本轮未做。
- **无 `?run=` 时四页显示的是错误面板样式**（「这一页没能打开」），而"还没选运行"其实是正常
  状态，不是故障。文案与去处都对，只是读起来像出了错。属打磨项。

## 发卡工具在本轮暴露并修好的两个缺陷

`tools/apply_patch.py` 是发卡落盘工具（不在任何 git 仓库内，不随项目分发）。它两次**静默丢补丁**：

1. **一个 `### PATCH:` 头下的第 2..n 个替换块被丢弃。** 卡格式明确允许一个文件多个块，GLM 也
   确实这么发，但旧正则把头和紧随的第一个围栏粘死。丢掉的是 `field.js` 的图例修复，
   一声不吭。改为：头拥有直到下一个 `###` 之前的**全部**块，并打印解析到几个文件几个块。
2. **空的 NEW（纯删除）解析错位，还吞掉下一个块的标记。** `=======` 直接顶着 `>>>>>>> NEW`
   时，旧正则要求捕获组里有换行，匹配不上就继续往后扫，把后一个块的标记吃了进去。
   删除是家常便饭，不是边缘情况。这个缺陷正是上面第 3 条污染 `modality.js` 的根源。

两条都是「静默丢失」——本项目反复付学费的同一类问题。修完后解析器会报出它看到了什么。
