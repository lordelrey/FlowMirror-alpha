## 验收中发现并修掉的缺陷

按发现顺序，全部由 GLM 按卡修复、由本记录逐项复验。

1. **`/api/images/<sha>` 永远 404。** 展示包 `posts.json` 只带图片的 sha256（文件名不外泄），
   服务端却拿 sha 去查文件名表。结果：配了 `--images-root` 也永远看不到真图，而这是界面上
   唯一能看见真图的路径。改服务端按 sha 反查文件名，**每次请求仍重算 sha256 比对**。
2. **随仓库分发的样本打不开。** `loadRun` 只在 `runs/out/<tag>` 下找，样本在 `web/samples/`。
   在 Pages 上（没有 `runs/out/`）等于白分发。`data.js` 两条路径都失败后改为查一次
   `web/samples/index.json` 并按其 `path` 重试，命中时在 `warnings` 里注明"这是演示样本"。
3. **`modality.js` 被落盘工具写进了补丁标记**，整个模块语法错、该页打不开。见下节。

## 已知限制（不是缺陷，但读者应当知道）

- **静态模式下必有一条控制台 404**：`probeLocalApi()` 去问 `/api/runs` 在不在，静态服务当然
  没有。这是**探测本身**，不是错误；浏览器无法静默失败的 fetch。所以第 1 项的判据是
  「没有**意外的**控制台错误」，不是字面的零。
- **ES 模块受浏览器缓存影响**：`?cb=` 只作用于 `index.html`，`import './data.js'` 的 URL 不变，
  改动后首次打开可能仍跑旧模块。验收时靠换端口（换源）绕开。部署到 Pages 后，回访者也可能
  拿到旧模块——若在意，给模块 import 加版本查询串。本轮未做。
- **无 `?run=` 时四页显示的是错误面板样式**（「这一页没能打开」），而"还没选运行"其实是正常
  状态，不是故障。文案与去处都对，只是读起来像出了错。属打磨项。

## 发卡工具在本轮暴露并修好的两个缺陷

`tools/apply_patch.py` 是发卡落盘工具（不在任何 git 仓库内，不随项目分发）。它两次**静默丢补丁**：

1. **一个 `### PATCH:` 头下的第 2..n 个替换块被丢弃。** 卡格式明确允许一个文件多个块，GLM 也
   确实这么发，但旧正则把头和紧随的第一个围栏粘死。丢掉的是 `field.js` 的图例修复，
   一声不吭。改为：头拥有直到下一个 `###` 之前的**全部**块，并打印解析到几个文件几个块。
2. **空的 NEW（纯删除）解析错位，还吞掉下一个块的标记。** `=======` 直接顶着 `>>>>>>> NEW`
   时，旧正则要求捕获组里有换行，匹配不上就继续往后扫，把后一个块的标记吃了进去。
   删除是家常便饭，不是边缘情况。这个缺陷正是上面第 3 条污染 `modality.js` 的根源。

两条都是「静默丢失」——本项目反复付学费的同一类问题。修完后解析器会报出它看到了什么。

### critical（三条，均已复现、已修、已复验）

**C1 · 本地服务把整个仓库端出去了。** 服务以仓库根为静态根启动，于是任何一个
未认证的 GET 都能取到：

| 路径 | 修前 | 修后 |
|---|---|---|
| `/config/api.yaml` | **200，264 字节，含一枚 49 字符的 api_key** | 404 |
| `/.git/config` | 200 | 404 |
| `/flowmirror/engine/loop.py` | 200 | 404 |
| `/data/funds/nav_cache.json` | 200 | 404 |

模块开头的说明写着"密钥不经过这个服务"。它经过了。
`--images-root` 那道"不许指向仓库内"的检查也因此形同虚设——仓库本来就全在外面。

**C2 · 没有 Host 校验，构成 DNS rebinding 的前置条件。** 绑 127.0.0.1 挡不住外部页面
把自己的域名解析到 127.0.0.1；这类请求带着我们从未签发过的 Host 到达。
实测：伪造 `Host: evil.example` 打 `/api/runs` 修前返回 **200**，修后 **403**。
静态路径同样。

**C3 · 首页对任何已载入的运行都抛异常。** `home.js` 在词表改名 `STATUS_ZH →
RUN_STATUS_ZH` 之后仍引用旧名。第 1 项验收只在**没有** `?run=` 的情况下点过七个 tab，
那条路径不走这段代码，所以漏了。这是验收设计本身的缺口，不是执行疏忽——
**带运行**与**不带运行**是两条独立路径，两条都要走。

### major（八条，全部已修）

- `POST /api/run` 不校验来源：`text/plain` 的表单提交即可启动一次引擎运行。
  现在缺 JSON content-type 返回 400，跨源 `Origin` 返回 403。
- 界面元素用了臂色与三个保留语义色（`--step-active`、`--local-badge`、链接、`.i-I1/I2/I3`）。
  最糟的是创意意图 `I2` 用了 `--signal`：回放页里它离人口场图例只有几厘米，
  而那里橙色的意思是"已签署确认书"——同一页教了同一个颜色两种含义。改为不靠色相区分。
- 配置页打印的"等效命令"标签漏了 `_s${seed}`，与按钮实际写入的目录不是同一个，
  最后那行"然后打开 web/?run=…"指向一个不存在的运行。
- 审计页把本机绝对路径打到屏幕上。导出器在展示包里已经抹掉它，原始产物路径要一致。
- `agent.js` 把颜色写进 `style=` 只经 `esc()`，而 `esc()` 不转义分号；另外四个模块都另有
  一道颜色白名单。补齐（用 `panels.js` 现成的，不发明新的）。
- `data.js` 的臂色回退**按下标取**：两臂 `T`/`TV` 在取不到 CSS 变量时把 `TV` 画成 `TC` 的紫色。
  浏览器里有样式表时不发生，但这个回退恰恰没能守住"臂色只属于臂"。改为按臂名取。
- `audit.js` 判 `has_run_meta`，服务端发的字段是 `has_meta`，那个徽章永远不显示。
- 契约 §1 的 `Tally` 块描述的字段名在代码里不存在；RUNBOOK 写了一条不存在的
  GitHub Pages 部署。两处文档都改成实际情况。

### minor（三条，全部已修）

`field.js` 图例用词与 `vocab.js` 漂了；计数条漏了漏斗里的"点击"一格；
