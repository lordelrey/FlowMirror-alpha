## 新查明的事实（每一条都改变了做法）

1. **真模型路径从未成功过一次。** 盘上 52 个运行、17,014 条缓存全是替身模型。唯一一次真调用尝试（`runs/out/probe_ratelimit`，09-07 15:03，6 并发，glm-4.6v，coding-plan 端点）缓存里 80 个决策 × 5 次尝试**全部 HTTP 429**。当天同一把 key 正在并行跑 GLM 5.3 写码卡，所以无法区分是「配额被写码卡吃光」还是「coding-plan 端点不服务 glm-4.6v」。**阶段 0 的探针就是为了分清这两者。**
2. **429 会变成永久缓存洞。** `runtime.py:338-357` 把任何非 200 归为 `http_error`，退避 5s×k 重试 4 次后，`decide()` 把失败**写进缓存当终态**；重放时洞照旧；且传输失败计入 `decision_failure_halt`（2%）。一阵限流就会**杀掉整次运行并污染缓存**。
3. **卡片上的「热度：N 赞」不是点赞数。** `loop.py:424` 写的是 `heat_prev` = `hot_score` = log10(赞+2收藏+3评论+1)/(age+1)^1.8（`channels/feed.py:126`）。首次展示日恒为 0。**种子热度实验必须建立在真实计数上**，这要改提示（`prompt_sha` 会动，需预注册）。
4. **逐帖点赞/收藏从未进日志。** `apply_decision` 只累进当日计数，`dec` 行只有总数。§C 的因变量与逐帖社会测度都算不出来，要补 `p_like`/`p_save` 字段。
5. **发帖事件不带 `note_id`**（`world.py:884`），跨运行身份靠导出器重放才能恢复。§D 的合规标签需要这个连接键。
6. **文字描述组今天只有 OCR。** 内容池没有 `image_caption_frozen` 字段，`data_pipeline/cn/caption_frozen.py` 存在但**从未批量跑过**。预注册 A1 写的 TC = OCR + 一句中性描述。要么跑批量（约 800 张图，glm-4.6v，后台），要么修订预注册为「TC = OCR」。**默认跑批量**——TC−T 与 TV−TC 的分解是头条实验的全部意义。
7. **只换 `--seed` 不是独立重复。** agent 的随机流、开局盈亏、定投目标都挂在 `run_tag` 上（`world.py:578/590/663`），只有平台流挂在 `seed`（`loop.py:968`）。**五个种子 = 五个不同的 (run_tag, seed) 对**，配置文件要分开写。
8. **卖出在引擎里是完整的。** 提示明说「申购或赎回」（`prompt.py:110,124`），schema `action ∈ {buy, redeem, none}`，非持仓赎回判违规（`prompt.py:559`），引擎按 0.5% 费率成交并累加实现盈亏（`loop.py:904-925`）。**缺的是**：买入日期（`inv.hold[code]` 只是份额浮点数，无批次）、`act` 行上的实现盈亏字段、任何卖出侧分析。替身模型的赎回分支 09-08 才修通。

## C · 种子热度实验（Muchnik–Aral–Taylor 2013 设计）

**估计量**：同一世界内、帖子之间随机化的处理对照——每条笔记首次展示日，随机把卡片上的点赞计数抬高 k（`plus`）或如实（`ctrl`），比较后续互动、评论、点击。不需要跨种子比对「同一条笔记」，旧方案卡住的身份锚点问题**不存在**。现实对应：**刷量/买赞对基金营销有没有用**——正是 2026《办法》第十条禁「未经核实的数据」的对象。

- 配置 `heat_seed: {enabled: false, k: 10, p_treat: 0.5}`。发帖时（`loop.py:1209-1211`，`birth[pid]=t` 之后）`treat = rng_for(run_tag, "heat_seed", pid).random() < p_treat`——**派生流**，`rng_platform` 与每个 `inv.rng` 不动。分组写在 `post` 行（给 `publish_day` 加 `heat_seed=None` 参数，单行落地）。**只在开启时**写字段 → 关闭时哈希不变。
- 显示：卡片构造（`loop.py:1332-1335`）用 X1 的 `likes_prev`；若 `enabled and t == birth[pid] and treat == plus`，`likes = likes_prev + k`。**只改卡片上的数字**：`heat`/`likes` 累加器与 `rank_feed(heat_prev…)`（`loop.py:1282`）不动，两组曝光完全相同，估计的是纯展示效应。首日真实值恒为 0，所以三档（抬高/如实/压低）在首日退化为两档；t+1、t+2 显示真实值，看级联。
- 反诱导：卡片用 `check=False` 加入（`prompt.py:442`），种子只是「热度：{n} 赞」里的数字，A–E 块不变 → `check_anti_priming`（`prompt.py:99`）不会触发也不会泄露；不进记忆（`loop.py:681`）与反思。
- 分析 `flowmirror/analysis/social_proof.py`（≤300 行）：逐帖首日展示与点赞/收藏/评论（来自 X1 的 `p_like/p_save` 与 `cmt`），t+1、t+2 同样（级联），点击/申购；plus−ctrl 在 P(like|imp) 首日与到 t+2 累计上的差；运行内按帖聚类自助，跨运行种子级 t；按模态组、按意图分层。k 在 100×12 试跑后按首日展示计数中位数定，写进预注册。
- **主因变量改为级联乘数**：到 t+2 累计多出的互动 ÷ k。乘数 > 0 是预注册方向；**乘数 > 1 且逐日增长 = 正反馈存在（TwinMarket 自我实现预言的对应物）**，乘数衰减 = 系统自我修正。两种结果都是结论。
- **单基金集中选项** `heat_seed.focus_fund: null|<code>`：置为某基金代码时，种子只施加在该基金的帖子上（内容池里单只基金最多 5 条笔记，"机构只发一只基金"做不了，集中社会证明是唯一可行的爆款打造）。宏观终点：该基金申购份额路径、同族溢出、跨种子路径依赖。
- **修正阶段**：拿到注意力爆发的基金，之后 5 日内的赎回率与舆论翻转是否高于对照基金（真实净值外生，部分会跌；这条链依赖 §B 的卖出侧）。放进 `sell_side.py` 或 `social_proof.py`。
- 测试 `tests/unit/test_heat_seed.py`：关闭 → 与基线日志逐字节相同；开启 → `post.heat_seed ∈ {plus, ctrl}`，处理卡片首日显示 +k、之后真实值，`heat_prev` 与 `imp` 行与关闭时**完全相同**（曝光不变性）。
- 卡：C1 loop/world/schema PATCH、C2 分析、C3 测试。2.5 操作日。运行：参考格 3 种子 `heat_seed.enabled: true`（与主网格分开，保持模态预注册干净）。
