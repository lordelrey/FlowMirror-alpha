# FlowMirror 社会层实施方案

日期：2026-09-09。适用基线：`3468436` 之后的社会层修订。

## 1. 研究问题

本阶段检验的是一条可中断的机制链：机构内容获得注意，评论作者被识别，关注关系改变后续接触，后续接触可能改变自主交易，交易进一步改变基金层资金分布。大 V、跟单和资金集中都是待观察结果，不是 agent 的预设目标。

当前论文优先研究“多模态金融内容如何经由平台分配和社会关系改变资金配置”。基金申赎影响底层资产价格需要现金缓冲、组合调仓、资产流动性和外部订单承接等额外机制，暂不混入本次社交探针。

## 2. 本批实现

### 2.1 推荐关注的端到端可达性

平台推荐块中的句柄现在与卡片评论作者、既有关注对象一起进入决策解析器的可见范围。修订前，推荐账号虽然出现在提示中，模型选择后仍可能被记为 `unknown_handle`。关注提示里的示例也改为与真实句柄一致的六位十六进制形式。

该修订只影响社交图开启的路径；十六份预注册配置不修改。

### 2.2 严格时序候选跟单

跟单统计现在要求同一基金满足：

`关注时点 <= 被关注者申购日 < 关注者申购日 <= 关注时点 + 3 日`

同日行为在引擎中是同步决策，不计为跟单。该指标仍称为“严格时序候选跟单”，不能仅凭先后关系写成因果影响；同质性、共同曝光和共同基金机会仍需对照。

### 2.3 运行安全

`script/run_grid.py` 只在 `run_meta.json` 顶层 `status` 为 `ok` 时跳过运行。预算停止、决策失败、不变量失败、损坏报告或缺少状态的报告均视为未完成。Windows 进程检查失败时拒绝启动，而不是按零进程继续。

新增 `script/run_social_probe.py`，专门执行 100 人 × 5 日真模型社交探针。它具备以下边界：

- `--dry-run` 零写入、零子进程、零付费调用；
- 同时检查引擎与 `run_grid.py` 驱动，发现任一冲突即拒绝；
- 从 `main_ref_s2027` 确定性派生配置，不修改十六份配置；
- 已有派生配置只有语义完全相同时才复用，绝不覆盖不一致配置；
- 单次运行、失败即停、不自动重试；
- 完成后强制免费重放，再运行 influence 分析；
- 输出关注边、关注者、关注意图、`unknown_handle` 和坏行计数；零关注不是运行失败。

## 3. 使用顺序

先查看计划：

```powershell
cd "D:\Desktop\ABM paper\flowmirror_v7"
python script/run_social_probe.py --dry-run
```

正式执行：

```powershell
python script/run_social_probe.py
```

正式命令必须在无人值守网格驱动和所有引擎进程均停止后执行。当前正在运行的旧进程不会热加载后来推送到 GitHub 的代码；GitHub 更新也不会改变它已经载入内存的运行逻辑。

现有 `run_grid.py` 不会自动把社交探针插入五个 `main_ref` 与 `main_nosuit` 之间。若研究日程要求恰好在五个参考种子后执行，应在该边界显式停止网格驱动，确认没有引擎进程，再使用上述探针脚本。未经业主授权，不自动停止当前网格。

## 4. 探针判读

- 有关注边：社会关系形成在该模型与五日条件下可行，随后进入多种子的机制比较。
- 零边且 `unknown_handle=0`：报告“该条件下未观察到自发关注”，不修改提示去追逐阳性结果。
- 零边且存在 `unknown_handle`：属于解析或可见范围故障，先修工程路径，不解释为社会发现。
- 有关注意图但无落边：沿“可见句柄 → `p_follow_users` → violations → `st/follow_user`”逐层定位。

100×5 是可行性诊断，不能把 500 个 agent-day 当作独立统计重复，也不能替代多种子运行。

## 5. 后续最小可证伪实验

第一组采用 2×2：关注可记录但不改变再曝光，对比关注对象评论前置；中性等量随机推荐，对比按粉丝数推荐。保持推荐槽位、候选池和展示信息一致，分别报告关系集中与资金集中。

第二组研究机构视觉选择：同一金融事实制作受控视觉版本，保持基金代码、收益、费用、风险和时间区间一致，只改变布局与信息显著性；比较静态素材策略与依据滞后聚合反馈更新的策略。点击、长期持有和风险适配应分开报告。

只有在这些微观链条获得稳定多运行证据后，再单独设计“基金净流入 → 现金缓冲与调仓 → 底层资产订单 → 价格与净值 → 后续信念”的市场反馈扩展。
