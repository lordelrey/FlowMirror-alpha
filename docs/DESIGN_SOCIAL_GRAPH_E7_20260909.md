# 大 V 层实现方案（E7）· 2026-09-09

**问题**：`social_graph.enabled: true` 的真模型探针产生关注边 0 条。已排除"模型不愿关注"这个解释——它压根看不到句柄。
**结论**：现有实现有四处断点，两处是设计缺陷。本文给出最小且诚实的修法、预注册影响、以及分两步的验证计划。
**约束**：所有改动必须在 `social_graph_on` 门内，主网格（开关关闭）逐字节不变，预注册 D23 的十六份配置 sha 表不动。

---

## 一、诊断：四处断点

全部数字来自 `runs/out/live_pilot_100x12`（100 人 × 12 日真模型）与免费替身转储 `runs/out/mockcheck_social/prompts/inv_00012_d1.txt`。

### 断点 1 · 句柄被舆论标签闸门吞掉

`flowmirror/agents/prompt.py` 的 `render_social` 在舆论标签为 `no_signal` 时**整块返回空串**，而句柄与粉丝数只渲染在这个块里。舆论标签又要求该帖前一日至少 4 条评论（`flowmirror/channels/feed.py` 的 `climate_for(min_n=4)`）。

| 项 | 实测 |
|---|---|
| 有评论的（帖, 日）对 | 72 个 |
| 其中清过 4 条门槛的 | 35 个 |
| 卡片带评论块的曝光（现状） | 1,613 / 7,200 = **22.4%** |
| 若只要求"前一日有 ≥1 条评论" | 2,994 / 7,200 = **41.6%** |

### 断点 2 · 谁能成名由 agent id 决定（更严重）

`top_comments` 的排序键是 `(-粉丝数, -对发帖机构的熟悉度, agent_id 升序)`。运行开始时所有人粉丝为 0、熟悉度多为 0，**agent_id 升序就成了唯一有效键**。

| 选取规则 | 有机会被看见的作者 | 单人最多被选中 |
|---|---|---|
| 现行（id 升序） | 60 / 100 人，且固定是 id 最小的那批 | 12 次 |
| 派生流公平抽签 | 78 / 100 人 | 8 次 |

现行规则下"谁能成为大 V"由 agent 编号决定，这是**硬编码的等级，不是涌现**。论文若声称观察到意见领袖的自发形成，这条会被审稿人一击致命。

### 断点 3 · 指令与内容不一致

`INSTR_FOLLOW_ZH` 只要 `social_graph_on` 就无条件附加，即使当天卡片里零个句柄。实测替身转储里 `follow_users` 指令存在、真实 `@u` 句柄 0 个。模型被邀请关注它看不见的人，容易产出 `unknown_handle` 违规。另外指令里的举例句柄 `@u3f9a` 是 5 位十六进制，E6 已把真实句柄改为 6 位，举例未同步。

### 断点 4 · 关注没有实质后果

`rank_feed` 的三源推荐里有 `follow` 槽位，但它读的是 `inv.follow`（关注的**机构**），不是 `inv.following_users`（关注的**人**）。关注一个人只换来"你关注的人昨天"最多 3 行摘要，不影响信息流排序。回报太弱，模型缺少关注的动机。

## 二、方案 E7：三处必要改动

### E7-1 · 句柄脱离舆论标签

`render_social`：当 `social_graph_on` 且该卡有 t−1 评论时，即使标签为 `no_signal` 也渲染摘录行；表头用中性措辞「昨日评论（共 n 条）」，**不带**舆论倾向短语。

不动 `climate_for(min_n=4)` 那条门槛——它防止稀薄评论伪造舆论多数，仍然正确。真实平台上"看得见作者是谁"和"这条帖的舆论倾向是什么"本来是两件事，现在的实现把它们错误地绑在了一起。

预期效果：句柄曝光面 22.4% → 41.6%。

### E7-2 · 公平初始曝光

`top_comments` 增加一个 `salt` 关键字参数；tie-break 由 `agent_id` 升序改为 `sha256(salt + agent_id)` 的字典序。主键仍是粉丝数降序，次键仍是熟悉度降序，**只有最末一层的平手规则变了**。

引擎调用点 `flowmirror/engine/loop.py:1437` 传 `salt=f"{run_tag}|{t}|{pid}"`。这不引入新随机源，与 `rng_for` 的派生流思路一致，重放安全。

预期效果：可能被看见的作者从 60 人升到 78 人，且不再由编号决定。一旦有人获得第一个粉丝，粉丝数就接管主键，富者愈富的回路才真正闭合。

### E7-3 · 指令条件化并修正举例

`build_decision_messages`：`INSTR_FOLLOW_ZH` 改为**仅当本次卡片集合里至少有一个可见句柄时**才附加。同时把举例句柄从 `@u3f9a` 改成 6 位（如 `@u3f9a2`），与 `handle_of` 的实际格式一致。

## 三、可选放大器 E8：平台级「值得关注」块

在提示里加一个平台级小块，展示 t−1 时刻粉丝最多的 3 个账号（句柄、粉丝数、主立场），**仅当至少一人有 ≥1 粉丝时出现**。

这是富者愈富最直接的放大器，也是真实平台"推荐关注"模块的对应物。冷启动时该块不存在，所以第一批关注仍须由 E7 的评论区可见性催生。

**建议**：E7 先落地并做真模型探针；只有在探针证明"模型愿意关注但边太少"时才加 E8。若探针显示模型完全不关注，E8 也救不了，那时应把"LLM agent 不自发建立社交连接"作为边界结论写进论文。

---

## 四、为什么这是最小且诚实的修法

- **不动主网格**：三处改动全在 `social_graph_on` 门内，开关关闭时提示与日志逐字节不变，`runs/main_*.json` 与 `runs/heat_seed_*.json` 的 sha 不受影响。只有 `runs/emerge_*.json`（开关开）的 `prompt_sha` 会变，而这三次运行还没开始跑。
- **不放松统计门槛**：`min_n=4` 保留。我们修的是"身份可见性"被错误耦合到"舆论标签"上，不是把门槛调松。
- **不新增随机源、不新增门禁**：E7-2 用确定性摘要做平手规则，重放校验仍然是唯一验收标准。
- **不预设结论**：E7 只保证模型**看得见**关注对象，不保证它会关注。看不见是缺陷，看得见却不关注是发现。

## 五、预注册影响

D31 需要修订，记录三件事：

1. 句柄与粉丝数的渲染不再受舆论标签约束（仅在 `social_graph.enabled` 为真时生效）；
2. 热评平手规则由 agent id 改为 `sha256(run_tag|t|post_id|agent_id)`，理由是前者让"谁成名"由编号决定，不构成涌现；
3. 关注指令仅在存在可见句柄时出现；开启态 `prompt_sha` 因此变动，关闭态不变。

零结果措辞照旧：若关注边仍为 0，报告为"在本模型与本窗口下未观察到自发的社交连接形成"，措辞档 `collective_qualitative`。

## 六、验证计划与成本

| 步骤 | 内容 | 成本 | 判据 |
|---|---|---|---|
| 1 | 替身验证 | 免费 | 关闭态与 `runs/out/acc_e6` 逐字节相同；开启态句柄出现在 ≥40% 的卡片上；同一（帖, 日）下被选中的三位作者不再是 id 最小的三人 |
| 2 | 单元测试 | 免费 | `render_social` 在 no_signal + 有评论 + 开关开时返回非空且含句柄；`top_comments` 在粉丝全 0 时的选取随 salt 变化而变化，且粉丝非 0 时粉丝仍为主键 |
| 3 | 真模型探针 **100 人 × 5 日** | 约 600 次调用、约 2 小时 | 是否出现第一条 `st.what == "follow_user"` |
| 4 | 判读 | — | 有边 → 进涌现运行；零边 → 作为边界结论写入论文，并考虑 E8 |

**探针规模必须是 100 人，不能是 20 人。** 20 人规模下每人看到评论块的机会接近 0，零边不能证明任何事——今天的探针就栽在这里。

## 七、风险

模型可能看得见句柄仍然不关注，与"12 日内从不卖出"同一个模式：这一代 agent 对可选动作普遍消极。若如此，涌现章节的三条链里"意见领袖与回音室"这一条会退化为零结果，论文需要靠"注意力级联"（种子热度）与"机构规范收敛"两条撑起涌现层。这一点应在动手前让业主知情。
